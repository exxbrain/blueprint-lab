# Публикация на Cloudflare Pages под логином и паролем

Сайт собирается из закрытого репозитория. Открыть его можно только с заданными логином и паролем:
браузер сам показывает окно входа (HTTP Basic Auth). Zero Trust и Cloudflare Access для этого не нужны.

В репозитории для этого уже есть:

- `functions/_middleware.js` — проверка логина и пароля перед каждым запросом: страницами, файлами сборки
  и превью-адресами. Сами логин и пароль в репозитории не хранятся — только в настройках проекта Cloudflare;
- `.nvmrc` — Node 22 (нужен для `npm run check`);
- `public/_headers`, `public/robots.txt` и `<meta name="robots">` — запрет индексации.

Всё остальное делается в панели Cloudflare.

## 1. Подключить репозиторий к Cloudflare Pages

1. Панель Cloudflare → **Workers & Pages** → **Create** → вкладка **Pages** → **Connect to Git**.
2. Авторизуйте GitHub. На шаге выбора доступа укажите **Only select repositories** → `exxbrain/blueprint-lab`.
3. Настройки сборки:

   | Поле | Значение |
   |---|---|
   | Production branch | `main` |
   | Framework preset | `None` (или `React (Vite)`) |
   | Build command | `npm run check && npm run build` |
   | Build output directory | `dist` |
   | Root directory | пусто (корень репозитория — там лежит папка `functions`) |

   Зависимости Cloudflare ставит сам по `package-lock.json`. Если сборка жалуется на версию Node,
   добавьте переменную окружения `NODE_VERSION` = `22`.
4. **Save and Deploy**. Через пару минут сайт появится по адресу вида `https://blueprint-lab.pages.dev`
   (имя может отличаться, если `blueprint-lab` занято).

Пока не задан пароль (шаг 2), сайт отвечает «Вход не настроен» и никого не пускает.

## 2. Задать логин и пароль

1. Проект Pages → **Settings** → **Variables and Secrets** → **Add**.
2. Добавьте две переменные, обе с типом **Secret** (значение потом не видно даже в панели):
   - `AUTH_USER` — логин, любой, например `guest`;
   - `AUTH_PASSWORD` — пароль. Лучше длинный и случайный: попыток подбора ничто не ограничивает.
3. Если панель предлагает выбрать окружение, задайте их и для **Production**, и для **Preview** —
   иначе превью-адреса будут отвечать «Вход не настроен».
4. Переменные действуют на новые сборки: **Deployments** → последняя сборка → **Retry deployment**
   (или просто следующий пуш в `main`).
5. Проверьте в приватном окне браузера: должно появиться окно входа. Логин — в поле
   «Имя пользователя» (регистр не важен), пароль — как задан.

Если вы уже включали Cloudflare Access для проекта (**Settings → General → Access policy**), выключите его
и удалите Access-приложения в Zero Trust — иначе придётся входить дважды.

## 3. Дальше

- Каждый пуш в `main` пересобирает сайт; если `npm run check` упадёт, сборка не опубликуется.
- Сменить пароль — поменять `AUTH_PASSWORD` и пересобрать (Retry deployment). Браузеры, где уже входили,
  спросят пароль заново.
- Выйти из браузера Basic Auth не умеет: окно входа снова появится только после закрытия браузера
  или в приватном окне.
- Функция срабатывает на каждый запрос, а бесплатный тариф даёт 100 000 запросов функций в сутки.
  Одно открытие сайта — это несколько запросов, для личного показа хватит с запасом.
- Пароль один на всех, кому вы его дали. Если нужен отдельный вход для каждого и отзыв доступа
  по одному человеку — это уже Cloudflare Access (Zero Trust) с кодом на почту.
