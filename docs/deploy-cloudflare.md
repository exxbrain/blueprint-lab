# Публикация на Cloudflare Workers под логином и паролем

Сайт собирается из закрытого репозитория и открывается только с заданными логином и паролем:
браузер сам показывает окно входа (HTTP Basic Auth). Zero Trust и Cloudflare Access для этого не нужны.

В репозитории для этого уже есть:

- `wrangler.jsonc` — Worker `blueprint-lab`: статические файлы из `dist`, а перед ними — проверка входа.
  Ключевая настройка — `assets.run_worker_first: true`: без неё Cloudflare отдаёт файлы мимо Worker'а, то есть без пароля.
  Там же выключены отдельные адреса версий (`preview_urls: false`): у старых версий без пароля адрес остался бы открытым;
- `worker/index.js` — проверка логина и пароля. Сами логин и пароль в репозитории не хранятся — только в секретах Worker'а.
  Проверку прогоняет `npm run check`: если Worker пускает без пароля, сборка не публикуется;
- `.nvmrc` — Node 22 (нужен для `npm run check`);
- `public/_headers`, `public/robots.txt` и `<meta name="robots">` — запрет индексации.

## 1. Подключить репозиторий

Если Worker `blueprint-lab` уже создан (адрес `blueprint-lab.<аккаунт>.workers.dev`), переходите к шагу 2 и проверьте
настройки сборки: Worker → **Settings → Build**.

1. Панель Cloudflare → **Workers & Pages** → **Create** → **Import a repository** → `exxbrain/blueprint-lab`
   (GitHub-приложению Cloudflare дайте доступ только к этому репозиторию).
2. Настройки сборки:

   | Поле | Значение |
   |---|---|
   | Project name | `blueprint-lab` — должно совпадать с `name` в `wrangler.jsonc` |
   | Build command | `npm run check && npm run build` |
   | Deploy command | `npx wrangler deploy` |
   | Root directory | пусто |

   Если сборка жалуется на версию Node, добавьте переменную сборки `NODE_VERSION` = `22`.

Пока не заданы секреты (шаг 2), сайт отвечает «Вход не настроен» и никого не пускает.

## 2. Задать логин и пароль

1. Worker → **Settings** → блок **Variables and Secrets** (тот, что выше карточки **Build**; переменные внутри **Build**
   видны только во время сборки и для пароля не подходят) → **Add**, тип **Secret** (значение потом не видно даже в панели):
   - `AUTH_USER` — логин, любой без двоеточия, например `guest`;
   - `AUTH_PASSWORD` — пароль. Лучше длинный и случайный: попыток подбора ничто не ограничивает.
2. Нажмите **Deploy**, если панель предлагает. Секреты сохраняются при следующих выкладках; после добавления
   сайт начинает спрашивать пароль сразу.
3. Проверьте в приватном окне браузера: должно появиться окно входа. Логин — в поле
   «Имя пользователя» (регистр не важен), пароль — как задан. Из терминала:
   `curl -I https://blueprint-lab.<аккаунт>.workers.dev/` должен вернуть `401`.

## 3. Закрыть обходы

1. **Адреса версий.** Worker → **Settings → Domains & Routes** → **Version URLs** (Preview URLs) — должно быть
   **Disabled**. `wrangler.jsonc` выключает их при каждой выкладке; проверьте один раз после первой выкладки с ним.
2. **Лимит.** Бесплатный тариф даёт 100 000 запросов Worker'ов в сутки на аккаунт; Worker срабатывает на каждый файл.
   После лимита адрес `workers.dev` отвечает ошибкой, а не открывается без пароля. Для личного показа лимита хватит с запасом.
3. **Свой домен** (Settings → Domains & Routes → Add → Custom domain) идёт через тот же Worker — пароль спрашивается и там.
4. **Превью веток.** Workers Builds умеет собирать и другие ветки (Settings → Build → **Enable Preview Builds**); у таких
   сборок свои публичные адреса, и `preview_urls` на них не действует. Если превью не нужны — выключите.
5. **Не откатывайтесь** (Deployments → Rollback) на версии раньше коммита с `wrangler.jsonc` и `worker/`: у них пароля нет.
6. Проверку `npm run check` держите в команде сборки: она падает, если из `wrangler.jsonc` пропадёт `run_worker_first`
   или Worker начнёт пускать без пароля.

Если для этого репозитория раньше создавали проект **Pages** (`*.pages.dev`) — удалите его: в нём проверки пароля нет,
а каждый пуш в `main` выкладывал бы туда открытую копию.

## 4. Дальше

- Каждый пуш в `main` пересобирает и выкладывает сайт; если `npm run check` упадёт, выкладки не будет.
- Сменить пароль — поменять секрет `AUTH_PASSWORD`. Браузеры, где уже входили, спросят пароль заново.
- Выйти из браузера Basic Auth не умеет: окно входа снова появится только после закрытия браузера
  или в приватном окне.
- Пароль один на всех, кому вы его дали. Если нужен отдельный вход для каждого и отзыв доступа
  по одному человеку — это уже Cloudflare Access (Zero Trust) с кодом на почту.
