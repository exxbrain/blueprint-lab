# Публикация на Cloudflare Pages под логином и паролем

Сайт собирается из закрытого репозитория. Открыть его можно только с заданными логином и паролем:
браузер сам показывает окно входа (HTTP Basic Auth). Zero Trust и Cloudflare Access для этого не нужны.

В репозитории для этого уже есть:

- `functions/_middleware.js` — проверка логина и пароля перед каждым запросом: страницами, файлами сборки
  и превью-адресами. Сами логин и пароль в репозитории не хранятся — только в настройках проекта Cloudflare.
  Проверку функции прогоняет `npm run check`: если она пропускает без пароля, сборка не публикуется;
- `.nvmrc` — Node 22 (нужен для `npm run check`);
- `public/_headers`, `public/robots.txt` и `<meta name="robots">` — запрет индексации.

Всё остальное делается в панели Cloudflare.

**Важно: каждая сборка Pages остаётся доступной по своему адресу** вида `a1b2c3d4.<проект>.pages.dev`
со своим кодом и своими переменными. Сборка из коммита без `functions/` открыта всем, а сборка со старым паролем
пускает по старому паролю. Поэтому ниже есть шаги про удаление старых сборок.

## 1. Подключить репозиторий к Cloudflare Pages

1. Убедитесь, что в ветке `main` на GitHub уже есть папка `functions` — иначе первая сборка будет без пароля.
2. Панель Cloudflare → **Workers & Pages** → **Create** → вкладка **Pages** → **Connect to Git**.
3. Авторизуйте GitHub. На шаге выбора доступа укажите **Only select repositories** → `exxbrain/blueprint-lab`.
4. Настройки сборки:

   | Поле | Значение |
   |---|---|
   | Production branch | `main` |
   | Framework preset | `None` (или `React (Vite)`) |
   | Build command | `npm run check && npm run build` |
   | Build output directory | `dist` |
   | Root directory | пусто (корень репозитория — там лежит папка `functions`) |

   Зависимости Cloudflare ставит сам по `package-lock.json`. Если сборка жалуется на версию Node,
   добавьте переменную окружения `NODE_VERSION` = `22`.
5. **Save and Deploy**. Адрес сайта Cloudflare покажет в проекте. Имя `blueprint-lab.pages.dev` уже занято
   чужим сайтом, поэтому у вашего будет другое (например, с суффиксом) — проверяйте вход именно на нём.

Пока не задан пароль (шаг 2), сайт отвечает «Вход не настроен» и никого не пускает.

## 2. Задать логин и пароль

1. Проект Pages → **Settings** → **Variables and Secrets** → **Add**.
2. Добавьте две переменные, обе с типом **Secret** (значение потом не видно даже в панели):
   - `AUTH_USER` — логин, любой без двоеточия, например `guest`;
   - `AUTH_PASSWORD` — пароль. Лучше длинный и случайный: попыток подбора ничто не ограничивает.
3. Если панель предлагает выбрать окружение, задайте их и для **Production**, и для **Preview** —
   иначе превью-адреса будут отвечать «Вход не настроен».
4. Переменные действуют на новые сборки: **Deployments** → последняя сборка → **Retry deployment**
   (или просто следующий пуш в `main`).
5. Проверьте в приватном окне браузера: должно появиться окно входа. Логин — в поле
   «Имя пользователя» (регистр не важен), пароль — как задан.

## 3. Закрыть обходы

1. **Fail closed.** Бесплатный тариф даёт 100 000 запросов функций в сутки на весь аккаунт; ответы «нужен вход»
   тоже считаются. Если после лимита стоит режим «Fail open», Cloudflare отдаёт файлы сайта без функции,
   то есть без пароля. Проект → **Settings** → **Runtime** → **Fail open / closed** → **Fail closed**:
   после лимита сайт до полуночи по UTC отвечает ошибкой, но не открывается.
2. **Старые сборки.** **Deployments** → у каждой сборки, сделанной до появления пароля (или до смены пароля),
   меню **⋯** → **Delete deployment**. Последнюю рабочую сборку не трогайте.
3. **Превью веток.** Если превью не нужны: **Settings** → раздел сборок (**Builds**) → **Branch control** →
   **Preview branch control** → **None**. Тогда ветки, кроме `main`, не публикуются вовсе.

Если вы уже включали Cloudflare Access: приложение для основного адреса удалите — иначе вход будет двойным.
Встроенную политику для превью (**Settings → General → Access policy**) можно оставить: она дополнительно
закрывает адреса отдельных сборок и превью.

## 4. Дальше

- Каждый пуш в `main` пересобирает сайт; если `npm run check` упадёт, сборка не опубликуется.
- Сменить пароль — поменять `AUTH_PASSWORD`, пересобрать (Retry deployment) и удалить старые сборки:
  они продолжают пускать по старому паролю. Браузеры, где уже входили, спросят пароль заново.
- Выйти из браузера Basic Auth не умеет: окно входа снова появится только после закрытия браузера
  или в приватном окне.
- Одно открытие сайта — это несколько запросов к функции; для личного показа 100 000 в сутки хватит с запасом.
- Пароль один на всех, кому вы его дали. Если нужен отдельный вход для каждого и отзыв доступа
  по одному человеку — это уже Cloudflare Access (Zero Trust) с кодом на почту.
